# OS4: модель динамики квадрокоптера на C++

Перенос Simulink-модели `OS4dynamics_01.slx` (вместе с `QuaternionLib.slx` и
`OS4dynamics_01_init.m`) на C++14 для изучения. Код оформлен по образцу
проекта SimTVRS: дерево расчетных модулей `ICalculateElement`, обмен данными
через `share()`/`bindTo()` по идентификаторам из `globalNameID.h`, структуры
данных `T...`, комментарии Doxygen на русском. Модель лежит в `modules/os4`,
ядро в `kernel`. Настроечные, входные и выходные параметры модели доступны
по сети через модуль МППМ с тем же протоколом, что в SimTVRS.

Внешних зависимостей нет: нужен только компилятор C++14 и CMake.

## Сборка и запуск

```sh
cd cpp
cmake -S . -B build
cmake --build build
./build/os4test            # проверки модели
./build/os4sim             # моделирование 5 с, результат в os4sim.csv
./build/os4sim --realtime --time 0   # в реальном времени до Ctrl+C
python3 tools/plot_os4.py os4sim.csv os4sim.png   # графики (нужен matplotlib)
```

Параметры `os4sim`:

| Ключ | Смысл | По умолчанию |
|---|---|---|
| `--time T` | время моделирования, с (StopTime) | 5 |
| `--freq F` | частота расчета, Гц (1, 6.25, 12.5, 25, 50, 100, 200, 400) | 400 |
| `--dt H` | задать шаг вручную вместо `--freq`, с | — |
| `--out FILE` | CSV-файл результатов | `os4sim.csv` |
| `--decim N` | писать каждый N-й шаг | 4 (раз в 10 мс) |
| `--throttle V` | газ на все ESC, 0…1 | 0.5 (висение около 0.43) |
| `--tau V` | подавать на моторы момент V, Н·м, без модели ESC | ESC включен |
| `--simulink` | вариант «как в Simulink»: момент без Ip, угол лопасти = R, момент 0.1 Н·м без ESC | выкл. |
| `--realtime` | считать в реальном времени (1 с модели = 1 с по часам) | выкл. |
| `--mppm` | запустить МППМ на UDP-порту 9999 | выкл. |
| `--mppm-port N` | порт МППМ (включает МППМ) | 9999 |
| `--print P` | период вывода состояния в консоль, с модельного времени | 0.5 в реальном времени, иначе не выводить |

По умолчанию считается исправленный вариант: гироскопический момент
умножается на Ip, угол лопасти берется 12° из параметров. С ключом
`--simulink` модель повторяет Simulink один в один, включая его особенности
(см. ниже). В коде это признаки `gyroWithIp` и `useThetaTip` в `TOS4Options`.

Вход модели по умолчанию — газ `throttle[4]` на ESC (модуль `modules/esc`),
как у настоящего аппарата. В Simulink на винт подавался готовый момент;
этот режим включается ключом `--tau` или `--simulink` (признак `useESC`).

## Как устроен расчет

1. `DispOS4` создает дерево модулей: `OS4Vehicle` (с пятью подчиненными
   модулями) и `Report`.
2. `bind()`: каждый модуль получает указатели на данные, которые заявил
   через `bindTo()`. Например, `OS4Propeller` получает `ID_OS4_State`,
   `ID_OS4_Aero`, `ID_OS4_Input` и открывает `ID_OS4_Propeller`.
3. `init()`: `OS4Vehicle` регистрирует свои параметры в МППМ (если он
   запущен) и записывает начальные условия из `setup` в интеграторы.
4. Цикл: `OS4Vehicle::calculate()` делает шаг Рунге-Кутты 4-го порядка
   готовой функцией `math_func::rk4` из SimTVRS. Она работает с массивами,
   поэтому состояние упаковывается в `double[OS4_STATE_SIZE]`
   (`TOS4State::toArray/fromArray`), а правые части отдает
   `OS4Vehicle::SDU(in, out)`. Для каждой из 4 стадий вызывается
   `derivatives()`, которая кладет
   состояние стадии в `xEval` и по порядку вызывает `calculate()` у
   подчиненных модулей:

   ```
   AeroValue -> Gravity -> Fuselage -> Propeller -> Equations -> dx
   ```

   Затем `finite()` считает выходы (IMU, углы, датчики моторов),
   а `Report` пишет строку в CSV.
5. Частота расчета задается как в SimTVRS: `setFreq(ICalculateElement::Hz400)`
   в конструкторе `DispOS4`. Шаг 1/400 = 2.5 мс передается всем подчиненным
   модулям, один вызов `DispOS4::calculate()` делает один шаг RK4. Без
   `--realtime` шаги идут подряд с максимальной скоростью.

## Модуль ESC

`modules/esc/escModel` — отдельный модуль `ESCModel` (ID `ID_ESCModel`),
подчиненный `OS4Vehicle`. Он превращает газ 0…1 в момент на валу винта.
Модель простая, но физически согласованная: ток, напряжение и обороты
связаны через Kv, батарея разряжается.

1. ESC: коэффициент заполнения ШИМ догоняет команду с запаздыванием
   первого порядка, `duty += (throttle − duty)·(1 − e^(−dt/τ_esc))`.
2. Батарея: ЭДС `E = cells·(3.5 + 0.7·soc)`, под нагрузкой
   `U_bat = E − R_int·I_bat`, заряд `soc` убывает по израсходованным мА·ч.
3. Мотор постоянного тока без индуктивности (она дает постоянную
   времени около 0.1 мс, меньше шага): `K = 60/(2π·Kv)`,
   `U = duty·U_bat`, `I = (U − K·ω)/R` (не меньше нуля, ESC не тормозит),
   момент на валу `τ = K·(I − I0)`.
4. Ток батареи `I_bat = Σ duty_i·I_i`, мощность `U_bat·I_bat`.

Электрическая часть считается раз за шаг (2.5 мс) в `OS4Vehicle::calculate()`
перед шагом RK4. Чтобы момент правильно зависел от оборотов внутри шага,
ESC отдает характеристику мотора `τ = max(0, torque0 − slope·ω)`, а
`OS4Propeller` вычисляет по ней момент на каждой стадии RK4.

Параметры по умолчанию (`escSetupInit()`): мотор 2150 об/мин/В,
R = 0.1 Ом, I0 = 0.5 А, прямой привод, τ_esc = 5 мс, батарея 3S 2200 мА·ч,
R_int = 0.03 Ом. Они подобраны под винт модели (висение около 1130 рад/с),
это не данные аппарата OS4. С ними висение получается на газе около 0.43:
ток мотора около 3 А, батареи около 5.4 А, напряжение около 12.4 В.
Газ 0.5 по умолчанию дает подъем примерно 5 м/с.

## Реальное время

С ключом `--realtime` шаги вызывает поток `Thread` (`service/sys/threadManager`),
как в SimTVRS: `Thread thread("pthOS4", &disp, disp.timeStep());
thread.setUseTimer(true); thread.create();`. Поток будит расчет по часам
`std::chrono::steady_clock`: k-й шаг начинается в момент `start + k·step`.
Ожидание идет до абсолютного момента (`sleep_until`), поэтому ошибка не
накапливается. Если шаг начался позже своего момента, следующий начинается
сразу и растет счетчик `missingCallCount`: модель догоняет часы. По окончании
печатается число шагов, число опозданий и максимальное время шага.

Один шаг считается примерно за 0.05–0.2 мс при периоде 2.5 мс. Отдельные
опоздания бывают из-за того, что ОС будит поток с задержкой, а не из-за
расчета. Результат в реальном времени совпадает с быстрым расчетом (это
проверяет `os4test`).

Шага 2.5 мс достаточно для точности: самая быстрая постоянная модели
(индуктивный поток) 10 мс, а при уменьшении шага в 10 раз результат за 5 с
меняется меньше чем на 0.1 % (тоже проверяется в `os4test`).

Чтобы подключить регулятор или джойстик в реальном времени, достаточно
перед шагом записывать команду в `OS4_Input` (через МППМ или
`OS4Vehicle::setControl()`).

Вектор состояния (`TOS4State`, 21 переменная) соответствует интеграторам
Simulink: `X.pos`, `X.vel`, `R.w`, `R.q`, 4 интегратора `|ω|` и 4 интегратора `λ_0`.

## Доступ через МППМ

С ключом `--mppm` диспетчер создает модуль МППМ (`service/sys/mppm`), который
работает в своем потоке и отвечает на UDP-запросы на порту 9999. Протокол
и структуры пакетов (`THeadRequest`, `TMemRequest`, `TModuleRequest`,
`TSelectedRequest`) скопированы из SimTVRS без изменений, поэтому подходят
те же программы-клиенты. Поддерживаются все три типа запросов: поиск
индекса по имени (`R_T_LISTPM`), чтение и запись структуры целиком
(`R_T_MODULE`) и выбранных значений (`R_T_SELECTED`). Ответ уходит на адрес
отправителя и порт из `head.port`.

Модули OS4 и ESC регистрируют пять участков памяти (как `MsgRegMPPM` в SimTVRS):

| Имя | Структура | Размер | Назначение |
|---|---|---|---|
| `OS4_Setup` | `TOS4Setup` | 144 байт | настроечные параметры: начальные условия |
| `OS4_Input` | `TOS4Input` | 64 байт | входные параметры: газ на ESC или момент |
| `OS4_Output` | `TOS4Output` | 408 байт | выходные параметры: состояние, IMU, моторы |
| `ESC_Setup` | `TESCSetup` | 80 байт | параметры мотора, ESC и батареи |
| `ESC_Output` | `TESCOutput` | 200 байт | ШИМ, напряжения, токи, заряд батареи |

Смещения полей (все числа double, кроме `reset`):

`OS4_Setup`: `pos` 0, `vel` 24, `euler` 48 (крен, тангаж, курс в градусах),
`w` 72, `omega[4]` 96, `vInd` 128, `reset` 136 (uint8).
Новые начальные условия применяются, когда записан `reset = 1`: модель
перезапускается с ними, время начинается с нуля, `reset` сбрасывается.
С `--time 0` после касания земли модель не завершается, а ждет такого
перезапуска.

`OS4_Input`: `throttle[4]` 0 (газ 0…1, при `useESC`), `tau[4]` 32
(Н·м, ограничение 0…0.2, без ESC).

`ESC_Setup`: `kv` 0, `R` 8, `I0` 16, `gear` 24, `eta` 32, `tauEsc` 40,
`cells` 48, `capacity` 56, `Rint` 64, `socInit` 72.

`ESC_Output`: `duty[4]` 0, `U[4]` 32, `I[4]` 64, `torque0[4]` 96, `slope[4]` 128,
`Ubat` 160, `Ibat` 168, `power` 176, `soc` 184, `used` 192.

`OS4_Output`: `time` 0, `Ve` 8, `Xe` 32, `Vb` 56, `pqr` 80, `q` 104,
`euler` 136 (рад), `aero` 160 (Vb, Vinf, psi, theta, rho), `gyro` 216, `acc` 240,
`headingX` 264, `headingY` 288, `tau[4]` 312, `T[4]` 344, `omega[4]` 376.

Пример: `os4sim --realtime --time 0 --mppm`, затем клиентом МППМ записать
`OS4_Setup.pos.z = -10` и `OS4_Setup.reset = 1`: аппарат начнет заново
с высоты 10 м. Обмен по UDP проверяет `os4test`.

Как и в SimTVRS, МППМ пишет прямо в память модуля без блокировок, поэтому
значение, записанное посреди шага, вступает в силу со следующего шага.

## Уравнения

Системы координат: земная NED (ось z вниз), связанная x вперед, y вправо, z вниз.
Кватернион `q = [q0 q1 q2 q3]`, `q0` скалярная часть, умножение по Гамильтону,
`v_e = q ⊗ v_b ⊗ q*`.

**Твердое тело ("12 ODEs")**

```
dXe/dt = Ve
dVe/dt = (F_винты + F_корпус + [0 0 m·g]) / m
dp/dt  = ((Iyy − Izz)·q·r + Mx) / Ixx
dq/dt  = ((Izz − Ixx)·p·r + My) / Iyy
dr/dt  = ((Ixx − Iyy)·p·q + Mz) / Izz
dQ/dt  = ½ · Q̂ ⊗ [0 p q r],   Q̂ = Q / |Q|
```

**Винт i** (`[ ]` Bouabdallah 2007, `( )` Pounds 2007, `{ }` Simplício 2011)

```
V    = Vb + ω × r_i,   Vz = −V.z,   Vh = √(V.x² + V.y²)
h/R  = −z_i / R
λ_IGE = λ0 − λ0 / (16·max(h/R, ¼)²) · cutoff(h/R)       cutoff: 1 при h/R ≤ 2, 0 при h/R ≥ 3
C_T  = σ·a0/4 · (θ_t − (Vz/(ΩR) + λ_IGE))                [5.13]
dλ0/dt = (C_T − 2·λ0·√((Vh/ΩR)² + (Vz/(ΩR) + λ_IGE)²)) / τ_λ0   {2-58},{2-59}
C_Q  = max(C_T·√(C_T/2), 0.001)                          (3.4)
T    = ρ·πR²·R²·C_T·Ω²                                   [5.5]
Q    = ρ·πR²·R³·C_Q·Ω·|Ω|                                [5.6]
dΩ/dt = (τ − Q) / Ip                                     [2.30]
```

**Моменты на корпус**

```
Mb = Σ r_i × [0 0 −T_i]                      тяга
   + Ip·[−Σ dir_i·q·Ω_i,  Σ dir_i·p·Ω_i,  0] гироскопический (в Simulink без Ip)
   + [0 0 Σ −dir_i·τ_i]                      реактивный (от команды мотора)
```

**Корпус**: `F = Rz(ψ)·Ry(θ)·[−qS·CD, 0, −qS·CL]`, `CD = 0.65 − 0.45·cos θ`,
`CL = 0.5·sin 2θ`, момент корпуса равен нулю.

## Что выяснилось при переносе

Модель переносилась по проводке блоков в XML файла `.slx`. Несколько
мест ведут себя не так, как можно ожидать по названиям блоков:

1. **Угол лопасти θ_t равен R.** Блок `θ_t` (Fcn `u(1)`) берет первый элемент
   шины `geometry`, а шина собрана как `[R, θ_tip, c, r1..r4, Ab]`. В итоге в
   формулу тяги попадает R = 0.075, то есть угол ≈ 4.3°, а не 12° из `init.m`.
   С этим значением при Ω = 2100 рад/с тяга ≈ 1.5 Н на винт, сумма ≈ 5.9 Н
   при весе 6.4 Н, т.е. начальное состояние близко к висению. В C++ по
   умолчанию берется 12°: тяга сразу почти в 5 раз больше (≈ 6.8 Н на винт),
   поэтому при той же команде 0.1 Н·м аппарат заметно набирает высоту.
   Для висения с 12° нужна скорость винтов порядка 1100 рад/с.
2. **Гироскопический момент без Ip.** Множителя инерции винта нет. При
   одинаковых скоростях винтов `Σ dir·Ω = 0` и это не заметно, но при
   рыскании момент завышен в 1/Ip ≈ 16700 раз. В C++ по умолчанию исправлено.
3. **Пороги влияния земли заданы в радиусах винта**, а не в метрах:
   влияние земли включается ниже h/R = 3 (0.225 м), касание земли
   срабатывает при h/R ≤ ¼ (≈ 1.9 см).
4. Реактивный момент берется от командного момента мотора τ, а не от
   аэродинамического Q.
5. Плотность воздуха постоянна, ветра нет, центробежные моменты инерции
   не используются, момент корпуса равен нулю.

## Отличия C++ от Simulink

| Что | Simulink | C++ |
|---|---|---|
| Интегрирование | ode45, переменный шаг, RelTol 1e-3 | `math_func::rk4`, 400 Гц (шаг 2.5 мс) |
| Угол лопасти и гироскопический момент | θ_t = R, момент без Ip | 12° и Ip (ключ `--simulink` возвращает как было) |
| `θ = asin(−Vz/V∞)` при V∞ = 0 | деление на ноль | θ = 0 |
| `C_Q` при C_T < 0 | корень из отрицательного числа | C_T заменяется нулем, затем ограничение 0.001 |
| "Attitude Switch" (тяжесть вдоль −x) | есть | не переносился |
| Вход | момент на винт, Н·м | газ на ESC 0…1, модель мотора и батареи (`--tau` возвращает момент) |
| Касание земли | Stop Simulation + Assertion | сообщение и остановка, отключается `stopOnCollision` |

Числа из Simulink и C++ совпадут не до последнего знака из-за разных
решателей; для сравнения можно уменьшить RelTol в Simulink и шаг `--dt` в C++.

## С чего начать изучение

1. `modules/os4/os4Init.cpp`: все параметры в одном месте.
2. `modules/os4/os4Equations.cpp`: уравнения твердого тела, 30 строк.
3. `kernel/global/math_func.h`: кватернионы.
4. `modules/os4/os4Propeller.cpp`: самая содержательная часть, аэродинамика винта.
5. `modules/os4/os4Vehicle.cpp`: как модули связаны и как идет интегрирование.
6. `modules/esc/escModel.cpp`: ESC, мотор и батарея.

Подключить свой регулятор можно так: перед каждым шагом записывать
команду в `input` (или вызывать `OS4Vehicle::setControl()`) по данным `output`.
