# OS4: модель динамики квадрокоптера на C++

Перенос Simulink-модели `OS4dynamics_01.slx` (вместе с `QuaternionLib.slx` и
`OS4dynamics_01_init.m`) на C++14 для изучения. Код оформлен по образцу
проекта SimTVRS: дерево расчетных модулей `ICalculateElement`, обмен данными
через `share()`/`bindTo()` по идентификаторам из `globalNameID.h`, структуры
данных `T...` в `globalData.h`, комментарии Doxygen на русском.

Внешних зависимостей нет: нужен только компилятор C++14 и CMake.

## Сборка и запуск

```sh
cd cpp
cmake -S . -B build
cmake --build build
./build/os4test            # проверки модели
./build/os4sim             # моделирование 5 с, результат в os4sim.csv
python3 tools/plot_os4.py os4sim.csv os4sim.png   # графики (нужен matplotlib)
```

Параметры `os4sim`:

| Ключ | Смысл | По умолчанию |
|---|---|---|
| `--time T` | время моделирования, с (StopTime) | 5 |
| `--dt H` | шаг интегрирования, с | 0.001 |
| `--out FILE` | CSV-файл результатов | `os4sim.csv` |
| `--decim N` | писать каждый N-й шаг | 10 |
| `--tau V` | постоянная команда на каждый мотор, Н·м | 0.1 |
| `--gyro-ip` | умножать гироскопический момент на Ip | выкл. |
| `--theta-tip` | брать угол лопасти 12° из параметров | выкл. |

Без ключей `--gyro-ip` и `--theta-tip` модель повторяет Simulink один в один,
включая его особенности (см. ниже).

## Как устроен расчет

1. `DispOS4` создает дерево модулей: `OS4Vehicle` (с пятью подчиненными
   модулями) и `Report`.
2. `bind()`: каждый модуль получает указатели на данные, которые заявил
   через `bindTo()`. Например, `OS4Propeller` получает `ID_OS4_State`,
   `ID_OS4_Aero`, `ID_OS4_Control` и открывает `ID_OS4_Propeller`.
3. `init()`: `OS4Vehicle` записывает начальные условия в интеграторы.
4. Цикл: `OS4Vehicle::calculate()` делает шаг Рунге-Кутты 4-го порядка.
   Для каждой из 4 стадий вызывается `derivatives()`, которая кладет
   состояние стадии в `xEval` и по порядку вызывает `calculate()` у
   подчиненных модулей:

   ```
   AeroValue -> Gravity -> Fuselage -> Propeller -> Equations -> dx
   ```

   Затем `finite()` считает выходы (IMU, углы, датчики моторов),
   а `Report` пишет строку в CSV.

Вектор состояния (`TOS4State`, 21 переменная) соответствует интеграторам
Simulink: `X.pos`, `X.vel`, `R.w`, `R.q`, 4 интегратора `|ω|` и 4 интегратора `λ_0`.

## Уравнения

Системы координат: земная NED (ось z вниз), связанная x вперед, y вправо, z вниз.
Кватернион `q = [q0 q1 q2 q3]`, `q0` скалярная часть, умножение по Гамильтону,
`v_e = q ⊗ v_b ⊗ q*`.

**Твердое тело ("12 ODEs")**

```
dXe/dt = Ve
dVe/dt = (F_винты + F_корпус + [0 0 m·g]) / m
dp/dt  = ((Iyy − Izz)·q·r + Mx) / Ixx
dq/dt  = ((Izz − Ixx)·p·r + My) / Iyy
dr/dt  = ((Ixx − Iyy)·p·q + Mz) / Izz
dQ/dt  = ½ · Q̂ ⊗ [0 p q r],   Q̂ = Q / |Q|
```

**Винт i** (`[ ]` Bouabdallah 2007, `( )` Pounds 2007, `{ }` Simplício 2011)

```
V    = Vb + ω × r_i,   Vz = −V.z,   Vh = √(V.x² + V.y²)
h/R  = −z_i / R
λ_IGE = λ0 − λ0 / (16·max(h/R, ¼)²) · cutoff(h/R)       cutoff: 1 при h/R ≤ 2, 0 при h/R ≥ 3
C_T  = σ·a0/4 · (θ_t − (Vz/(ΩR) + λ_IGE))                [5.13]
dλ0/dt = (C_T − 2·λ0·√((Vh/ΩR)² + (Vz/(ΩR) + λ_IGE)²)) / τ_λ0   {2-58},{2-59}
C_Q  = max(C_T·√(C_T/2), 0.001)                          (3.4)
T    = ρ·πR²·R²·C_T·Ω²                                   [5.5]
Q    = ρ·πR²·R³·C_Q·Ω·|Ω|                                [5.6]
dΩ/dt = (τ − Q) / Ip                                     [2.30]
```

**Моменты на корпус**

```
Mb = Σ r_i × [0 0 −T_i]                      тяга
   + [−Σ dir_i·q·Ω_i,  Σ dir_i·p·Ω_i,  0]    гироскопический (без Ip, как в Simulink)
   + [0 0 Σ −dir_i·τ_i]                      реактивный (от команды мотора)
```

**Корпус**: `F = Rz(ψ)·Ry(θ)·[−qS·CD, 0, −qS·CL]`, `CD = 0.65 − 0.45·cos θ`,
`CL = 0.5·sin 2θ`, момент корпуса равен нулю.

## Что выяснилось при переносе

Модель переносилась по проводке блоков в XML файла `.slx`. Несколько
мест ведут себя не так, как можно ожидать по названиям блоков:

1. **Угол лопасти θ_t равен R.** Блок `θ_t` (Fcn `u(1)`) берет первый элемент
   шины `geometry`, а шина собрана как `[R, θ_tip, c, r1..r4, Ab]`. В итоге в
   формулу тяги попадает R = 0.075, то есть угол ≈ 4.3°, а не 12° из `init.m`.
   С этим значением при Ω = 2100 рад/с тяга ≈ 1.5 Н на винт, сумма ≈ 5.9 Н
   при весе 6.4 Н, т.е. начальное состояние близко к висению. Ключ
   `--theta-tip` подставляет 12°: тяга сразу вырастает почти в 5 раз (≈ 6.8 Н на винт).
2. **Гироскопический момент без Ip.** Множителя инерции винта нет. При
   одинаковых скоростях винтов `Σ dir·Ω = 0` и это не заметно, но при
   рыскании момент завышен в 1/Ip ≈ 16700 раз. Ключ `--gyro-ip` исправляет.
3. **Пороги влияния земли заданы в радиусах винта**, а не в метрах:
   влияние земли включается ниже h/R = 3 (0.225 м), касание земли
   срабатывает при h/R ≤ ¼ (≈ 1.9 см).
4. Реактивный момент берется от командного момента мотора τ, а не от
   аэродинамического Q.
5. Плотность воздуха постоянна, ветра нет, центробежные моменты инерции
   не используются, момент корпуса равен нулю.

## Отличия C++ от Simulink

| Что | Simulink | C++ |
|---|---|---|
| Интегрирование | ode45, переменный шаг, RelTol 1e-3 | RK4, постоянный шаг 1 мс |
| `θ = asin(−Vz/V∞)` при V∞ = 0 | деление на ноль | θ = 0 |
| `C_Q` при C_T < 0 | корень из отрицательного числа | C_T заменяется нулем, затем ограничение 0.001 |
| "Attitude Switch" (тяжесть вдоль −x) | есть | не переносился |
| Касание земли | Stop Simulation + Assertion | сообщение и остановка, отключается `stopOnCollision` |

Числа из Simulink и C++ совпадут не до последнего знака из-за разных
решателей; для сравнения можно уменьшить RelTol в Simulink и шаг `--dt` в C++.

## С чего начать изучение

1. `kernel/os4/os4Init.cpp`: все параметры в одном месте.
2. `kernel/os4/os4Equations.cpp`: уравнения твердого тела, 30 строк.
3. `kernel/global/math_func.h`: кватернионы.
4. `kernel/os4/os4Propeller.cpp`: самая содержательная часть, аэродинамика винта.
5. `kernel/os4/os4Vehicle.cpp`: как модули связаны и как идет интегрирование.

Подключить свой регулятор можно так: выключить `options.constControl`
и перед каждым шагом вызывать `OS4Vehicle::setControl()` по данным `output`.
